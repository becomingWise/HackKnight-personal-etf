# Website handoff: show the basket

The user wants the selected companies and their allocation. Selection explanations
are not part of the main screen. Render a basket title, a company table, and an
allocation chart.

## Agent response for display

The website implementation files are currently empty. Follow
[Teammate handoff](../TEAM_HANDOFF.md) for ownership and API integration.
If the backend includes an optional `basket` field, use this display shape:

```json
{
  "basket": {
    "title": "Your basket",
    "allocationMethod": "equal",
    "holdings": [
      { "symbol": "AAA", "name": "Company A", "weightPct": 33.33 },
      { "symbol": "BBB", "name": "Company B", "weightPct": 33.33 },
      { "symbol": "CCC", "name": "Company C", "weightPct": 33.34 }
    ]
  }
}
```

This example shows the format with placeholder identities. The live response
uses the companies produced by research. Starting percentages are computed by
the application's existing `startingWeights` function, not generated by Gemini.
The last row accounts for display rounding so the percentages sum to 100%.

| Field | Show to the user |
| --- | --- |
| `basket.title` | The basket heading |
| `basket.holdings[].name` | Company name |
| `basket.holdings[].symbol` | Stock ticker |
| `basket.holdings[].weightPct` | Percentage text and allocation-chart segment |
| `basket.allocationMethod` | Display `equal` as “Equal starting weights” |

Use `weightPct.toFixed(2) + "%"` for the label. An allocation bar or donut can
use these same values. Keep the entered idea above the result, and show the three
holdings as one basket. Do not infer dollars, units, prices, performance, or risk
scores from company names. Those fields need separate inputs or services.

The example above shows only the display basket. The controller's stock-service
port requires `summary` and `stocks` with only `symbol` and `name`, even when an
optional `basket` is included. Neither `research` nor `reason` is returned.
Lucas implements the agent and its internal source checks.

## If you use the existing controller

The controller already assigns the same starting weights and can later replace
them with validated market adjustments. Its current snapshots do not include the
agent's `basket` field. Subscribe to it and join company names with its **current**
holdings instead of continuing to show the agent's initial percentages:

```js
controller.subscribe(state => {
  if (state.view !== "dashboard") return;
  const names = new Map(state.stocks.map(stock => [stock.symbol, stock.name]));
  const basket = {
    title: "Your basket",
    allocationMethod: state.adjustment.status === "adjusted" ? "adjusted" : "equal",
    holdings: state.holdings.map(holding => ({
      ...holding,
      name: names.get(holding.symbol)
    }))
  };
  // Kieran: render basket using your own components.
});
```

Show a loading message while `status === "finding"`. On the dashboard, show the
equal starting basket immediately; `status === "adjusting"` can show adjustment
progress while retaining those rows. After adjustment finishes, read the current
`state.holdings`. Display `adjusted` as “Adjusted weights”. Failed or unavailable
adjustments keep the starting basket. Use `state.error` for a readable retry state.

The edit action calls `controller.editIdea()`; starting a fresh session calls
`controller.reset()`. This handoff specifies data and behavior; the website
teammate owns the components, styling, chart, and backend connection.
